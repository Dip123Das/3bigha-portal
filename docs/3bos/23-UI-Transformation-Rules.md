# UI Transformation Rules

## Human Journey First

A page must follow how a person naturally thinks, not the order of database fields.

## One Primary Task

Every page should make its main purpose immediately understandable.

## Progressive Simplicity

Show only information relevant to:

- the current identity;
- the current workspace;
- the present task;
- the Growth Plan;
- the person's experience level.

## Contextual Identity

Do not expose generic labels such as Vendor, Seller or Service Provider when a
respectful contextual identity is available.

## AI Visibility

Use simple human language such as:

- Preparing your requirement
- Checking your information
- Suggested for your review

Avoid exposing implementation terms such as AI agent, model, autonomous system
or generated output unless genuinely necessary.

## Responsive Behaviour

Mobile and desktop must be designed intentionally.

Do not rely on desktop layouts merely shrinking on mobile.

## Required States

Every workflow must define:

- initial state;
- loading state;
- empty state;
- validation state;
- error state;
- success state;
- recovery path.

## Preservation Rule

UI transformation must not remove working capabilities or break existing
production workflows.
